Pi-Bolt 0.9.5 does less work per turn and per prompt, on every platform: up to 20% less CPU per prompt in a long session,
up to 9% less in an interactive session, and on Windows 9% fewer file operations. It also fixes compiled-in extensions that
lost their skills and prompts, plugins built from a checkout that used a second copy of Pi, and a miscompile in the `-jit`
builds. Pi is 1.3.0, with four fixes from Pi's next release. Everything else is [0.9.4](0.9.4.md).

Measured on GitHub's runners, 0.9.4 as released against 0.9.5, with the same local fake model (Linux pinned to one CPU):

| CPU | Linux x86-64 | Linux ARM64 | macOS | Windows |
|---|---|---|---|---|
| A headless prompt (5 model turns) | 46 → 45 ms | 61 → 59 ms | 60 → 55 ms | 117 → 117 ms |
| An interactive session (5 prompts) | 144 → 131 ms | 200 → 187 ms | 218 → 210 ms | 364 → 333 ms |
| A prompt at 20 prompts into a session | 29.8 → 26.0 ms | 38.3 → 35.5 ms | 45.1 → 38.4 ms | |
| A prompt at 40 prompts (9 MB requests) | 64.3 → 61.7 ms | 75.7 → 75.1 ms | 79.1 → 63.5 ms | |

Startup, streaming and idle are unchanged. On Windows an interactive session makes 1,534 file operations instead of 1,689, and
in the ConPTY check the prompt is ready after 99.7 ms instead of 110.6 ms.

### Performance

- **Long sessions:** every request sends the whole conversation again, and serializing it was the cost that grew with the
  session. The serialized form of each long string (a tool result, an answer) is now kept from the request before and copied
  as it is, so each one is escaped once. The bytes sent are the same.
- **Streaming events** pass from the provider to the agent directly instead of through three streams that each read every
  event again.
- **Start:** the models are refreshed once instead of twice when an extension registers a provider, `models.json` is read and
  checked once instead of three times, and `models-store.json` is no longer rewritten when nothing in it changed.
- **Windows:** `fd` is no longer looked for as `fdfind` (Debian's name) in every PATH folder: a third of the PATH checks at
  start.

### Fixes

- **Compiled-in extensions** find the files beside their modules again: an extension that registers `skills/`, `prompts/` or
  themes from `import.meta.url` lost them when `pi-bolt compile` put it into the executable
  ([#53](https://github.com/opensec-git/Pi-Bolt/issues/53)). The script that prepares them also no longer exits without
  output when it is run through a symbolic link.
- **Plugins built from a checkout** (`scripts/build-pi.sh --plugins`) use the coding agent the executable runs, not a second
  copy of it, so a plugin that patches one of its classes takes effect
  ([#52](https://github.com/opensec-git/Pi-Bolt/issues/52), [#51](https://github.com/opensec-git/Pi-Bolt/pull/51) by
  [@Shrub24](https://github.com/Shrub24)).
- **`-jit` builds:** an `Array#sort` with a comparator that does arithmetic on whole numbers, once compiled by the JIT, could
  return them out of order (oven-sh/WebKit#792). The default builds were not affected; a new test guards them.
- **From Pi's next release:** automatic retry also for `request to ... failed` errors and more gateway errors, tool output
  that is only whitespace is sent as empty (some providers answered 400), and summaries for compaction and branches are no
  longer limited to a fixed number of output tokens.

### Install

```bash
curl -fsSL https://pi-bolt.opensec.in/install.sh | sh
```

```powershell
irm https://pi-bolt.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://pi-bolt.opensec.in/install.ps1 | iex"
```

or `pi-bolt update`, or `npm install -g --allow-scripts=pi-bolt pi-bolt`, or `bun add -g --trust pi-bolt`.
