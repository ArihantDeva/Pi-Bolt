Pi-Bolt 0.9.9 takes three fixes from Bun 1.4.4 and its WebKit into the engine, and fixes how a missing extension is
reported. Everything else is [0.9.8](0.9.8.md).

### Engine

- **Requests to model providers over TLS:** a connection whose TLS session breaks after its handshake is treated as a lost
  connection, so the request is retried as for any lost connection, instead of failing as a refused handshake
  ([oven-sh/bun#46409](https://github.com/oven-sh/bun/pull/46409)).
- **macOS, split DNS:** names are resolved with `DNSServiceQueryRecord`, so a lookup fails over between resolvers, as with a
  VPN that answers for some domains ([oven-sh/bun#44519](https://github.com/oven-sh/bun/pull/44519)).
- **Linux, a hang in garbage collection:** the collector suspends a thread with a signal, and the handler now reads where the
  thread was interrupted from the signal's context, which is right when the handler runs on an alternate signal stack
  ([oven-sh/WebKit#817](https://github.com/oven-sh/WebKit/pull/817), [oven-sh/bun#44982](https://github.com/oven-sh/bun/issues/44982)).

The runtimes are new; Pi is 1.4.0, as in 0.9.8.

### Pi-Bolt

- **A failed extension is reported once:** its message no longer repeats "Failed to load extension", and `pi-bolt --version`
  with an `-e` path that does not exist fails, with or without `-ne`, as every other mode does
  ([#88](https://github.com/opensec-git/Pi-Bolt/pull/88) by [@ArihantDeva](https://github.com/ArihantDeva)).

### Install

```bash
curl -fsSL https://pi-bolt.opensec.in/install.sh | sh
```

```powershell
irm https://pi-bolt.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://pi-bolt.opensec.in/install.ps1 | iex"
```

or `pi-bolt update`, or `npm install -g --allow-scripts=pi-bolt pi-bolt`, or `bun add -g --trust pi-bolt`.
