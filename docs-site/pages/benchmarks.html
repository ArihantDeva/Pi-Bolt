Benchmarks

Pi-Bolt against Pi as released, on stock Bun and on Node, on three machines. Medians of fresh processes, interleaved across the builds. Lower is better in every row.

How it is measured

  • The same work for every build. Each build runs the same prompts against a local server that replays the same model responses, so there is no network or provider variance.
  • Pi as released. "Pi on Bun" and "Pi on Node" are Pi 1.1.0 built from its release tag, not Pi-Bolt's tree.
  • Interleaved. Builds take turns, so a change in the machine's state affects all of them alike.
  • CPU time is user plus system time of the process. Memory is the process's own memory: the pages it wrote, not file pages it shares with the system.

The benchmark scripts, the method in full and the raw data are in the repository: BENCHMARKS.md.

PiG starts a little sooner and its single-prompt process is smaller; oh-my-pi streams a long answer with a little less CPU. Pi-Bolt uses the least CPU in sessions and per prompt, the least memory over a session, and writes large files fastest. oh-my-pi compacts a long conversation on its own, so the long session does not compare it (–).

Why a large file write takes so long on stock Pi

Those 20 to 40 seconds are not the disk. A model writes a file by streaming the write tool call's arguments, the whole file, a few characters at a time, so a 200 KB file arrives in thousands of chunks. Stock Pi parses and redraws the whole tool call again for every chunk: each chunk costs more than the last, and the total grows with the square of the file's size. Pi-Bolt processes only the new part of each chunk.

In the benchmark the model streams as fast as it can, so the cost shows as wall time. With a real model, which streams more slowly, it shows as CPU: about 40 seconds of it for a 200 KB file on stock Pi.

Measurements, not guarantees Each table comes from one machine. On other hardware the times differ; what carries over is the comparison.
